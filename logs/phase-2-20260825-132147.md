18	4. Classify turbine health and surface alerts.
19	5. Handle missing, late-arriving, and anomalous telemetry gracefully.

158	## 5. Data Layer (DuckDB)
159	
160	### 5.1 Ingest
161	
162	On first run (cached with `@st.cache_resource` so it happens once per process):
163	
164	```sql
165	CREATE TABLE farms AS SELECT * FROM read_csv_auto('farms.csv', header=true);
166	CREATE TABLE turbines AS SELECT turbine_id, farm_id, latitude, longitude
167	                        FROM read_csv_auto('turbines.csv', header=true);
168	CREATE TABLE telemetry AS SELECT * FROM read_csv_auto('telemetry.csv',
169	                        header=true, timestampformat='%Y-%m-%dT%H:%M:%SZ');
170	```
171	
172	Then:
173	
174	- Cast `timestamp` and `received_at` to `TIMESTAMP WITH TIME ZONE` (UTC).
175	- Create indexes: `CREATE INDEX idx_tel_turbine_ts ON telemetry(turbine_id, timestamp);` and `CREATE INDEX idx_tel_farm_ts ON telemetry(farm_id, timestamp);`
176	- **Deduplicate** on `(turbine_id, timestamp)`, keeping the row with the greatest `received_at` (a late-arriving record supersedes an earlier one for the same measurement time). The seed set has no duplicates; expanded sets may.
177	- Log a one-line ingest summary to the Streamlit sidebar/expander: row counts per table, telemetry time range, dedup count, count of rows with any NULL metric.
178	
179	### 5.2 Materialized helper view
180	
181	Create a `latest_telemetry` view — the most recent row per turbine by `timestamp` — since nearly every "current" figure derives from it:
182	
183	```sql
184	CREATE VIEW latest_telemetry AS
185	SELECT * FROM (
186	  SELECT *, ROW_NUMBER() OVER (PARTITION BY turbine_id ORDER BY timestamp DESC) rn
187	  FROM telemetry
188	) WHERE rn = 1;
189	```
190	
191	### 5.3 Query rules
192	
193	- **All** aggregation, filtering, and time bucketing happens in SQL. Do not pull the full telemetry table into pandas.
194	- Every query lives in `src/data/queries.py` as a named function with typed parameters. No SQL strings in UI code.
195	- Use parameter binding (`?`) — never f-string interpolation of user-influenced values.
196	- Cache query results with `@st.cache_data(ttl=...)` keyed on the parameters.

200	## 6. Domain Logic
201	
202	### 6.1 The clock — defining "now"
203	
204	The dataset is historical (Jan 2026 in the seed set), so wall-clock time would make every turbine permanently stale. `domain/clock.py` exposes:
205	
206	```python
207	def get_now(con) -> datetime:  # tz-aware UTC
208	```
209	
210	Resolution order:
211	
212	1. If env var `SIM_NOW` is set (ISO 8601), use it.
213	2. Otherwise use `MAX(timestamp)` across the telemetry table — i.e. the dataset's own latest measurement.
214	
215	Display the resolved "now" in the app header as `Data as of: 2026-01-02 23:55 UTC` so the operator is never misled about freshness. Every "current" and staleness calculation in the app uses this single function.
216	
217	### 6.2 Health classification
218	
219	Health is computed **per turbine**, from that turbine's latest telemetry record, by counting threshold breaches.
220	
221	**Statuses:**
222	
223	| Status | Color | Rule |
224	|---|---|---|
225	| Healthy | Green `#2E7D32` | Zero breaches |
226	| Warning | Orange `#ED6C02` | Exactly one *minor* breach |
227	| Critical | Red `#C62828` | One or more *major* breaches, **or** three or more *minor* breaches |
228	| Error | Gray `#757575` | Telemetry missing, stale, or structurally invalid |
229	
230	**Two minor breaches** falls between Warning and Critical as literally written. Resolve this by defining Warning as **one or two** minor breaches and Critical as **three or more** minor breaches (or any major). Document this in the README as a spec-gap decision.
231	
232	**Error takes precedence over everything.** A turbine is Error if any of:
233	
234	- No telemetry row exists at all.
235	- Latest `timestamp` is older than `now - STALE_AFTER_MINUTES` (default **15 min** = three missed intervals).
236	- Any of the five metrics is NULL, non-numeric, or outside its physically-possible range (below).
237	
238	**Thresholds** — all values live in `config.py` as a single dict so they can be tuned without touching logic:
239	
240	| Metric | Physically impossible (→ Error) | Minor breach | Major breach |
241	|---|---|---|---|
242	| `power_output_kw` | `< -50` or `> 5000` | `< 40%` of power-curve expectation while `4 ≤ wind_speed ≤ 15` | `≤ 0` while `4 ≤ wind_speed ≤ 25` |
243	| `wind_speed_ms` | `< 0` or `> 60` | `> 25` (cut-out exceeded) | — |
244	| `rotor_rpm` | `< 0` or `> 40` | `> 18.5` | `> 22.0`; **or** `< 0.5` while `4 ≤ wind_speed ≤ 25` |
245	| `blade_pitch_deg` | `< -5` or `> 95` | `> 25` while `power_output_kw > 100` | `> 40` |
246	| `gearbox_temp_c` | `< -40` or `> 200` | `> 95` | `> 110` |
247	
248	**Power-curve expectation** (a simple reference curve, not a model): linear ramp from 0 kW at 3 m/s (cut-in) to rated 3,500 kW at 12 m/s, flat at rated from 12–25 m/s, 0 above 25 m/s. Put it in `config.py` as `POWER_CURVE`. Its only use is the power-underperformance breach.
249	
250	`health.py` exposes:
251	
252	```python
253	@dataclass
254	class HealthResult:
255	    status: HealthStatus          # enum: HEALTHY/WARNING/CRITICAL/ERROR
256	    minor: list[Breach]           # each: metric, value, threshold, message
257	    major: list[Breach]
258	    errors: list[str]             # human-readable reasons for ERROR
259	
260	def classify(record: dict | None, now: datetime) -> HealthResult
261	```
262	
263	Pure function, no I/O — this is the most heavily unit-tested module.
264	
265	### 6.3 Farm health
266	
267	- **Farm health score** = fraction of its turbines that are Healthy, weighted: Healthy 1.0, Warning 0.6, Critical 0.0, Error excluded from the denominator (but see alert rule). Score ∈ [0, 1] drives the green→red dot color via a continuous colormap (`branca.colormap.LinearColormap` from red through amber to green).
268	- **Farm alert** (the exclamation icon): raised when **any** turbine at the farm is Critical, **or** when Error turbines exceed 20% of the farm's turbine count. Both conditions are configurable. The icon tooltip states which condition fired and how many turbines are involved.
269	- If a farm has zero turbines in `turbines.csv` (true for 8 of 10 seed farms), render its dot in Error gray with count `0` and a tooltip reading "No turbines registered." Do **not** crash or omit the farm.

349	## 9. NWP Layer — Interface + Stub
350	
351	Wind direction and air temperature have no source in the telemetry schema, so they come exclusively from here.
352	
353	Define in `domain/nwp.py`:
354	
355	```python
356	class NWPProvider(Protocol):
357	    def point_forecast(self, lat: float, lon: float, valid_time: datetime
358	                       ) -> PointForecast: ...
359	    def point_history(self, lat: float, lon: float,
360	                      start: datetime, end: datetime) -> list[PointForecast]: ...
361	    def grid(self, bounds: Bounds, variable: Literal["wind","temperature"],
362	             valid_time: datetime) -> GridField: ...
363	
364	@dataclass
365	class PointForecast:
366	    valid_time: datetime
367	    wind_speed_ms: float
368	    wind_direction_deg: float     # meteorological convention: direction wind is FROM
369	    air_temp_c: float
370	```
371	
372	Two implementations:
373	
374	1. **`StubNWPProvider`** — **the one wired up in v1.** Returns deterministic synthetic values seeded from `(lat, lon, valid_time)` so results are stable across reruns. Every value it returns is flagged `is_simulated=True`, and the UI must render a visible "Simulated" badge wherever stub data appears.
375	2. **`HRRRProvider`** — **ToDo stub only.** Class exists with full docstrings and correct signatures; every method raises `NotImplementedError`. Docstrings state the intended implementation: use `herbie-data` to fetch HRRR, select the nearest grid point to the **farm** coordinate (all turbines in a farm share the farm's conditions), derive wind speed/direction from the 80 m U/V components, and take 2 m temperature. Note that HRRR covers CONUS only, so farms outside that domain must degrade gracefully.
376	
377	Provider selection is a single line in `config.py` (`NWP_PROVIDER = StubNWPProvider`), so swapping in the real one later is a one-line change.

434	
435	| Situation | Behavior |
436	|---|---|
437	| Missing 5-min interval | Time series shows a genuine **gap** (insert NULLs at expected intervals via a generated time spine, `connectgaps=False`), not an interpolated line. |

447	## 12. Scalability Requirements
448	
449	The seed set is trivial; the expanded set will not be. Build for it from the start:
450	
451	- **Never** `SELECT *` from telemetry into pandas. All roll-ups are SQL aggregations.
452	- Persist DuckDB to a local file (`fleet.duckdb`) and skip re-ingest if the file exists and the CSV mtimes are unchanged. Show ingest time in the sidebar.
453	- Cache query results with `@st.cache_data`; key on level, entity ID, and window. Cache the DuckDB connection with `@st.cache_resource`.
454	- Time series must be **bucketed in SQL** (`time_bucket` / `date_trunc`) to a resolution appropriate to the window: 5 min for 24h, 1 hour for 7 days, 6 hours for full history. Never return more than ~2,000 points to the browser.
455	- Scatter plots down-sample above 5,000 points using deterministic reservoir sampling, with the sample size stated on the chart.
456	- Health classification for the map runs as a **single query** producing one row per turbine, then a vectorized classification pass — not a per-turbine query loop.
457	- Document in the README the path beyond this: partitioned Parquet on object storage, a columnar warehouse, pre-aggregated 5-min/hourly/daily rollup tables, and a streaming ingest path replacing CSV.

395	
396	**Objective:** Every SQL statement the application will ever run, as named, parameterized, typed
397	functions. No aggregation happens outside this file.
398	
399	**Target Files (create):** `src/data/queries.py`, `tests/test_queries.py`

401	**Data Contracts:** Every function's first parameter is `con: duckdb.DuckDBPyConnection`.
402	
403	```python
404	def get_farms(con) -> list[Farm]: ...
405	def get_turbines(con, farm_id: str | None = None) -> list[Turbine]: ...
406	def get_turbine_counts_by_farm(con) -> dict[str, int]: ...
407	def get_max_timestamp(con) -> datetime | None: ...
408	def get_latest_records(con, farm_id: str | None = None) -> list[TelemetryRecord]: ...
409	def get_latest_record_for_turbine(con, turbine_id: str) -> TelemetryRecord | None: ...
410	
411	def get_power_timeseries(
412	    con, *, level: Level, entity_id: str | None, start: datetime | None,
413	    end: datetime, bucket: str, max_points: int,
414	) -> pd.DataFrame: ...            # columns: bucket_start (tz-aware UTC), power_kw (float)
415	
416	def get_total_energy_mwh(con, *, level: Level, entity_id: str | None) -> float: ...
417	def get_current_power_kw(con, *, level: Level, entity_id: str | None, now: datetime,
418	                         stale_after_minutes: int) -> float: ...
419	def get_scatter_data(con, *, turbine_id: str, x_metric: str, y_metric: str,
420	                     start: datetime | None, end: datetime, max_points: int) -> pd.DataFrame: ...
421	                                   # columns: x (float), y (float)
422	def get_fleet_bounds(con) -> Bounds | None: ...
423	def get_farm_turbine_bounds(con, farm_id: str) -> Bounds | None: ...
424	```
425	
426	**Step-by-Step Instructions:**
427	
428	1. Create `src/data/queries.py`. Module docstring states: *the sole owner of SQL in this project.*
429	2. Implement every function above. Rules:
430	   - Bind all parameters with `?`. The only value ever interpolated into a SQL string is `bucket`
431	     and `x_metric`/`y_metric`, which **must** first be validated against `config.BUCKET_BY_WINDOW`
432	     values and `config.METRICS` respectively; an invalid value raises `QueryError`. Never accept a
433	     free-form string into SQL.
434	   - `get_power_timeseries` buckets with `time_bucket(INTERVAL <bucket>, timestamp)` and
435	     `SUM(power_output_kw)` grouped by bucket, filtered by level (fleet = no filter, farm =
436	     `farm_id = ?`, turbine = `turbine_id = ?`) and by `timestamp >= ? AND timestamp <= ?`.
437	     Order ascending. If the result exceeds `max_points`, raise `QueryError` — the caller is
438	     responsible for choosing a coarse enough bucket, and a silent truncation would mislead.
439	   - `get_power_timeseries` must **also return gap rows**: left-join the aggregation onto a generated
440	     time spine (`generate_series`) at the bucket interval so missing intervals appear as rows with
441	     `power_kw = NULL`. This is what makes `PROJECT_SPEC.md` §11's "genuine gap" rendering possible.
442	   - `get_total_energy_mwh` = `SUM(power_output_kw) * (TELEMETRY_INTERVAL_MINUTES / 60.0) / 1000.0`.
443	   - `get_current_power_kw` sums `power_output_kw` from `latest_telemetry`, excluding rows where
444	     `timestamp < now - stale_after_minutes` and rows where `power_output_kw IS NULL`.
445	   - `get_scatter_data` selects the two metrics with both `IS NOT NULL`, within the time window, and
446	     down-samples above `max_points` using a deterministic modulo stride
447	     (`WHERE rn % CAST(? AS BIGINT) = 0` over a `ROW_NUMBER()`), never `ORDER BY random()`.
448	   - `get_fleet_bounds` / `get_farm_turbine_bounds` compute `MIN`/`MAX` of lat and lon.
449	     `get_farm_turbine_bounds` returns `None` when the farm has no turbines.
450	   - Wrap every `con.execute` in `try/except duckdb.Error` and re-raise as `QueryError` with the
451	     function name and the original message.
452	3. Write `tests/test_queries.py` against the `db_con` fixture. At minimum:
453	   - `get_turbine_counts_by_farm` includes `FARM03` with count 0.
454	   - `get_latest_records(farm_id="FARM01")` returns exactly the `FARM01` turbines.

525	
526	**Objective:** The project's most important module. Convert a telemetry record into a `HealthResult`.
527	Pure function, exhaustively tested at every threshold boundary.
528	
529	**Target Files (create):** `src/domain/health.py`, `tests/test_health.py`
530	
531	**Data Contracts:**
532	
533	```python
534	def classify(record: TelemetryRecord | None, now: datetime,
535	             stale_after_minutes: int) -> HealthResult: ...
536	
537	def classify_many(records: Sequence[TelemetryRecord], turbine_ids: Sequence[str],
538	                  now: datetime, stale_after_minutes: int) -> dict[str, HealthResult]: ...
539	
540	def farm_health_score(results: Sequence[HealthResult]) -> float | None: ...   # 0..1, None if no turbines
541	def farm_alert(results: Sequence[HealthResult]) -> str | None: ...            # reason text, or None
542	def status_counts(results: Sequence[HealthResult]) -> dict[HealthStatus, int]: ...
543	```
544	
545	**Step-by-Step Instructions:**
546	
547	1. Implement `classify` with this exact precedence:
548	   - **Step 1 — ERROR checks (short-circuit, return immediately with all reasons collected):**
549	     a. `record is None` → `errors=("No telemetry received",)`.
550	     b. `clock.is_stale(record.timestamp, now, stale_after_minutes)` → error reason naming the record
551	        age in minutes and the threshold.
552	     c. Any metric in `config.METRICS` is `None`, `NaN`, or outside `[physical_min, physical_max]` →
553	        one error reason per offending metric, naming the metric, value, and the bound crossed.
554	   - **Step 2 — collect breaches** (record is valid; evaluate all rules, do not short-circuit):
555	     - `gearbox_temp_c`: `> major_max (110)` → major; else `> minor_max (95)` → minor.
556	     - `rotor_rpm`: `> major_max (22.0)` → major; else `> minor_max (18.5)` → minor.
557	       Additionally `< ROTOR_STALL_RPM (0.5)` while `wind_speed_ms` is inside
558	       `ROTOR_STALL_WIND_RANGE` → **major** (stalled rotor in operating wind).
559	     - `blade_pitch_deg`: `> major_max (40)` → major; else `> minor_max (25)` **and**
560	       `power_output_kw > PITCH_CONDITIONAL_POWER_KW (100)` → minor.
561	     - `wind_speed_ms`: `> minor_max (25)` → minor (cut-out exceeded). No major.
562	     - `power_output_kw`: `<= 0` while `wind_speed_ms` is inside `POWER_ZERO_WIND_RANGE` → **major**;
563	       else `< POWER_UNDERPERFORM_FRACTION × POWER_CURVE_EXPECTED_KW(wind_speed_ms)` while
564	       `wind_speed_ms` is inside `POWER_CHECK_WIND_RANGE` → **minor**.
565	     - A metric contributes **at most one** breach; major supersedes minor for the same metric.
566	   - **Step 3 — classify:** any major, or `len(minor) >= config.MINOR_TO_CRITICAL` → `CRITICAL`;
567	     else `len(minor) >= 1` → `WARNING`; else `HEALTHY`.
568	     Add `# SPEC-GAP: 2 minor breaches → WARNING (see PROJECT_SPEC.md §16)`.
569	2. Every `Breach.message` is a complete sentence naming metric, observed value with unit, and the
570	   threshold crossed — this text renders directly in the turbine dashboard.
571	3. `farm_health_score`: weighted mean over non-ERROR results using `config.FARM_SCORE_WEIGHTS`.
572	   Returns `None` if the farm has zero turbines or every turbine is ERROR.
573	4. `farm_alert`: returns a reason string when any result is `CRITICAL`
574	   (`"2 turbines in Critical state"`) or when the ERROR fraction exceeds
575	   `config.FARM_ALERT_ERROR_FRACTION` (`"3 of 10 turbines reporting Error (30%)"`); otherwise `None`.
576	   If both fire, return both, joined by `"; "`.
577	5. Write `tests/test_health.py` as a **table-driven** suite. Required cases — for each threshold,
578	   assert at the boundary, just below, and just above:
579	   - Clean record → `HEALTHY`, no breaches.
580	   - `gearbox_temp_c` = 94.9 → healthy; 95.0 → healthy (rule is strictly `>`); 95.1 → 1 minor →
581	     `WARNING`; 110.1 → major → `CRITICAL`.
582	   - `blade_pitch_deg` = 44 with power 2000 → major → `CRITICAL`.
583	   - `blade_pitch_deg` = 30 with power 50 → **no breach** (conditional power gate).
584	   - `rotor_rpm` = 0.2 with wind 10 → major → `CRITICAL`.
585	   - `power_output_kw` = 0 with wind 10 → major → `CRITICAL`.
586	   - `power_output_kw` = 400 with wind 10 (expectation ≈ 2722, 40% ≈ 1089) → minor → `WARNING`.
587	   - Exactly 2 minor breaches → `WARNING`. Exactly 3 minor breaches → `CRITICAL`.
588	   - Any metric `None` → `ERROR` with a reason naming that metric.
589	   - `gearbox_temp_c` = 250 → `ERROR` (physically impossible), **not** Critical.
590	   - `record.timestamp` 16 minutes before `now` → `ERROR`; 14 minutes → not stale.
591	   - `record is None` → `ERROR`.
592	   - `farm_health_score` on `[HEALTHY, WARNING, CRITICAL]` → `(1.0 + 0.6 + 0.0)/3`.
593	   - `farm_health_score` on all-ERROR and on empty → `None`.
594	   - `farm_alert` fires on one CRITICAL; fires at 21% ERROR; does not fire at 19% ERROR with no
595	     CRITICAL.
